⚠️ VULNERABILITY EXPLANATION

This site used client-side hidden form fields to store the price before sending it to the server. The backend blindly trusted the price parameter in the POST request without server-side validation.


What you did with Burp Suite:

  • Intercepted the POST /checkout/pay request
  • Found the hidden field: price=XXXX
  • Modified it to: price=0
  • Forwarded the tampered request → Server accepted it!

🛡️ HOW TO FIX THIS (Remediation)

  • ✅ Never trust client-side data — Always recalculate price server-side using the product ID and quantity from your database
  • ✅ Store cart in server session — Keep cart state on the server, not in hidden fields or cookies
  • ✅ HMAC signing — If you must pass values client-side, sign them with a secret key (HMAC-SHA256) and verify on the server
  • ✅ Re-validate at payment — Before charging, always re-fetch product prices from DB and compare
  • ✅ Anomaly detection — Flag orders where price < expected threshold for manual review
